# W2-03c native frontend and character screens

Contract revision 1; base `8d1ec79b34e8282b525436dc90abfb327b4d65e9`. This continues W2-03b's presenter checkpoint. Evidence candidate for coordinator review; no runtime, visual, durable-transition or gate pass is claimed.

## Native screen host

`SLHFrontendWidget` builds Slate widget trees for Frontend, Characters/Continue, Creation, Character Sheet and Inventory/Equipment entirely in C++. Settings is an explicitly unavailable adapter screen. No Widget Blueprint or binary asset is needed. The host uses a uniformly scaled 1920×1080 safe-area canvas, opaque token surfaces, engine-default type, token control heights, scrolling controls, and a persistent input legend. V-03 colours, type sizes, safe insets, control padding, spacing and focus stroke come from `LHUIStyle.h`. Focus has an amber outline plus leading `>` independent of hover. Modal controls have their own outline and chevron; background controls are removed while a modal is open. This is a scrollable native first implementation, not a pixel-for-pixel reproduction of V-02's multi-pane wireframes or a visual approval.

Every data read and submit goes through `FLHUIPresenter`. Widgets retain only presentation drafts: creation inputs, allocation deltas, item/slot selection and recovery acknowledgment. They never write a canonical snapshot or calculate derived stats, equipment eligibility, growth or resources. Unknown values remain Unknown; prototype/disputed number formatting remains explicit, including fractional resource values. No historical mechanics values, font assets or reference images were added.

Frontend offers New, Continue/Characters, Settings and confirmed Quit. Characters cycles owner profiles, selects stable character identity, displays profile status/recovery loss warning, and requires separate recovery acknowledgment before a confirmed continue. Session failure strings remain separate from command reasons and remain visible. Creation supplies an editable name plus a gamepad character picker (letters, digits, space, hyphen and apostrophe; Append/Erase/Done), owner appearance choices and four owner questions, roll/reroll/legal review, owner field errors and explicit creation confirmation. Keyboard typing uses Slate's native editable text/IME path; gamepad character-picker Unicode breadth is deliberately limited pending localization work. Editing invalidates preview. Form fields survive rejection and modal rebuilds.

Character Sheet displays owner level, XP, debt, separate point pools, historical maxima/current resources, base attributes and pending deltas. Five steppers use left/right, confirm to increment, or mouse Previous/Minus and Next/Plus buttons. Reset affects the draft only. Unchanged command deltas are explicit resolved zeros. A nonempty allocation requires owner review and a cancel-default modal. Rejections preserve the draft; acceptance clears it. Switching journal tabs with a draft asks to discard; cancellation keeps the draft and screen. Inventory renders inventory selections, quantities, eight equipment slots including Quiver, explicit Equip/Unequip intent, owner review and confirmation. Slot swaps are one command; UI never pre-clears gear. Missing equipment modifiers/requirements remain Unknown. The current read seam does not provide localized item names or definition-specific quiver descriptions; it displays definition identifiers and bound instance IDs as fallback metadata and makes no invented unlimited-ammunition claim.

Accepted creation is latched by the presenter; widget allocation/equipment/continue confirms latch until a deliberate draft/selection edit. Held confirm/back repeats are consumed. Modal confirm starts at Cancel. Back closes the child modal first and restores its launching control. Accepted creation cannot be discarded while the owner finishes durability. A rejected synchronous intent may be retried, using the presenter's fresh request identity after definitive rejection.

## Input and ownership seams

D-pad/arrows/Tab traverse the presenter's ordered controls without wrapping and set actual Slate keyboard focus, scrolling the focused control into view. Left/right adjusts selectors and drafts. Enter/South confirms, Escape/East backs out, and shoulders switch journal tabs through the dirty-draft guard. Mouse controls call the same operations. Left-stick input crosses a prototype 0.6 threshold once and rearms only when both axes are below 0.25; this prevents held-stick actions after screen/modal changes. These thresholds are authored UI presentation tuning, not mechanics. Physical-device disconnect/reconnect, repeat ergonomics, Wayland focus and rendered readability still need host validation.

Presentation-only additions to `ILHUIReadOwner` are optional/default-unavailable `QuestionCatalog`, `ReviewAllocation` and `ReviewEquipment`. Question entries carry stable IDs, prompts and answer IDs; appearance choices retain one selection per dotted presentation category. Authority still validates compatibility and all required choices. Reviews provide legal status and explanatory summary; the widget does not claim legal allocation/equipment if a review adapter is absent. These are UI seams only, not changes to frozen Core revision 1. Existing W2-03b owner implementations continue compiling. Integrator should provide labels, full initial-kit/durability review, detailed provenance and eligibility through an expanded presentation adapter as those owners become available.

`ALHFrontendGameMode` has no gameplay pawn and uses `ALHFrontendController`. The controller constructs `ULHInputConfig`, installs UI or Creation Enhanced Input context as the screen changes, and sets UI-only Slate input. Slate consumes navigation/confirm/back, avoiding a second Enhanced Input submit path. `InstallPresenter` replaces the bootstrap with owner-bound adapters; install before BeginPlay or after synchronous intent completion (replacement is refused while the existing presenter is pending). Adapters must outlive the presenter/widget. Bootstrap returns empty profiles/unresolved preview/rejected commands and permits a confirmed application exit; it is not a fabricated playable authority or save fixture. No simulation pause, gameplay resume, durable creation/continue transition or save retry can be promised by this frontend-only adapter; the session owner must implement those policies.

## Frontend map generation

`ULHGenerateFrontendMapCommandlet` creates `/Game/Lighthaven/Maps/L_Frontend` with the native frontend game mode. It checks for a read-only existing map, creates the directory and saves through Unreal editor APIs. `bash build/generate-frontend-map.sh` has the same root fail-fast, project environment, editor prerequisite and lockable-map check as the dev-map generator. Coordinator runs it as a normal host user, owns/locks the binary, reviews it and commits the generated map. No `.umap` was hand-written or generated here. Adding the map to packaging/startup configuration is outside these owned paths and belongs to the integrator.
