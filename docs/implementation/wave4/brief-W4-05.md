## What exists
- `UI/`: Slate screens on presenters (`LHUIPresenter.*`, `LHFrontendWidget.*`, journal with Character/Inventory tabs), `ILHUIReadOwner`/`ILHUISessionOwner` (implemented by `FLHWave2Session`). No HUD, dialogue, services, spell bar, death or pause screens.
- `Input/LHInputConfig.cpp`: native Enhanced Input actions; no hotbar/spell actions. `Input/LHTargeting.h`: `ILHControlTarget`.
- `Framework/LHPlayerController.cpp`: `RequestSelectedAttack` returns `UnresolvedRules` with a session; `Interact` handles only portals (nearest within 250 cm + LOS), else broadcasts `OnInteractRequested`. NPCs are `ALHInteractableMarker` (World/, DefinitionId `NPC.*`, instance GUIDs in `hub-graybox.md`), not `ILHControlTarget`.
- DTO `FLHQuestRecord` (accepted/completed/rewarded, EligibleKillCount, Flags, TurnInClaim) and `FLHBossRecord`. No quest catalog or logic. Core has no quest/dialogue class (D03), so the catalog is native data here.

## Work
1. **Quests and interaction (`Source/Lighthaven/Quests/`).**
   - Native catalog: `Quest.SamaritanRats` (accept at `NPC.Samaritan`; count only Brown Rat kills settled **after** acceptance; 15 required; single turn-in for 2500 XP, distinct from kill XP; claim via `LHSave::QuestTurnInRewardId`). `Quest.BalorkReturn`: authored Stage 1 objective (defeat Balork → return to the church → an **Interact** topic at `NPC.BrotherKiran` completes it; travel/arrival never grants progress, `world-systems.md`; completion text must not claim the historical quest chain; no numeric reward (source has none)). Church tutorial and descent objective dialogue (`NPC.BrotherKiran`; new text, no invented offers). **Bat-wing quest (Uranos): deferred** (Matt): needs a future mechanic where *completing the quest* grants the item; don't author it.
   - Topic IDs `Topic.*` (selectable; keyword optional). Every NPC with W4-07 offers gets a `Topic.Services` opening the services screen (no offer logic). Healer: `NPC.Nevanis` `Topic.Heal` restores health per the lookup (amount/cost/restrictions; a Prototype, e.g. free full heal, only where `missing`); show eligibility feedback.
   - `ELHCommandReason LHQuests::ExecuteInteract(FLHSaveSnapshot&, const FLHInteractContext&, const FLHInteractRequest&)`: valid target, proximity (lookup distance, else Prototype), topic availability by quest state, atomic, no UI-side rewards. W4-06 adds receipts (W4-04 helpers); tests compose them to prove replay. `FLHInteractContext` carries the resolved NPC DefinitionId/entity, distance and LOS (W4-06 fills it from actors).
   - `class FLHQuestKillObserver : public ILHKillObserver` (rat counting; Balork defeat → objective stage). Persisted acceptance, completion and reward stay independent; count ignores corpse cleanup.
2. **Controller and input (`Framework/LHPlayerController.*`, `Input/`).** In a live session, Attack submits `FLHUseAbilityRequest` for the selected hotbar ability via `ILHCommandHandler` (fresh RequestId + session epoch; retry reuses it), targeting the enemy's stable entity. Interact picks nearest portal → NPC interactable marker → corpse (loot): sends `FLHRequestTravelRequest`/`FLHInteractRequest` or opens the loot panel. Corpse actor → container: `ALHEnemyCharacter::GetLife()` → `LHRewards::CorpseContainerFor(RunId, Life)` (W4-04). Movement and attack gate only on `FLHWave2Session::IsBlocked()` (W4-06 narrows it to travel freeze / missing content / dead-awaiting-respawn; a save in flight never freezes movement); add no save gating. UseAbility is runtime-only (D16): no save wait between swings. Add hotbar actions 1–6 + controller shoulder-held selection (`01-game-design.md` control map) in `Input/`, keeping `Lighthaven.Controls.InputConfigParity` (keyboard + pad for every action). Dev-map path (no session) unchanged.
3. **UI (`UI/`).** Slate, V-03 style, keyboard + gamepad reachable, per V-02/V-04 wireframes: HUD (health, mana, target nameplate/health, objective line, save status), spell/ability bar (selection, cooldown/mana feedback), NPC dialogue (topics, heal, quest accept/turn-in), services screen (lists offers, submits Train/Learn/Buy/Sell; never computes prices), **loot panel** (corpse item/gold rows with quantity; sends `FLHTakeLootRequest` with the right Kind; shows full-inventory rejection), **item use** (inventory Use and a hotbar item slot send `FLHUseItemRequest` for the owned item, fresh RequestId, retry reuses it; show its rejections), death/respawn screen, pause (true simulation pause per D16; contexts restored with release gating), boss completion notice. Extend `ILHUIReadOwner`/`ILHUISessionOwner` with **defaulted** virtuals that W4-06 implements, e.g. `HudState()`, `DialogueTopics(const FLHEntityId&)`, `ServiceOffers(const FLHEntityId&)` (UI-side view struct in `UI/`), `CorpseContents(const FLHEntityId&)`, `RequestRespawn()`, `SetGameplayPaused(bool)`. UI never includes `Services/`, `Rewards/` or `AI/` headers.
4. Doc `docs/implementation/quests-ui.md`: quest/topic tables with provenance, interface additions for W4-06, Prototype choices (heal rule, distances), deferred items (bat-wing quest).

- `Lighthaven.Quests.RatErrandEligibility`: pre-acceptance kills don't count; post-acceptance Brown Rats do; other species don't; count survives save/reload and corpse cleanup.
- `Lighthaven.Quests.SingleTurnIn`: turn-in grants 2500 XP once; repeat, replay and reload never re-grant; completion before 15 rejects unmutated.
- `Lighthaven.Quests.HealerInteraction`: heal applies the declared rule; out-of-range, no-LOS and dead player reject.
- `Lighthaven.Quests.BalorkCompletionFlow`: defeat sets the objective; arrival alone changes nothing; the Brother Kiran topic completes it once; flags survive reload/travel and Balork's 15:00 respawn (a second kill grants nothing); no historical-chain claim text.
