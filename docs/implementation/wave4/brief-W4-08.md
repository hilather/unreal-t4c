## Work
1. **Freeze a rev-1 fixture first.** Before changing anything, encode the Persistence test fixture (with its own ruleset/content compatibility) using the current code and commit the bytes as a frozen vector (`LighthavenTests/Persistence/LHSchemaRev1Fixture.inl`) plus their SHA-256. After the bump nothing can produce rev-1 bytes. Real G3-era saves are rejected on `ContentRevision` once the W4 catalog lands (accepted by Matt, Q9); never use one for the migration test.
2. **Core contract (`Core/LHCommands.h`).** `FLHUseItemRequest { FLHRequestId Request; FLHEntityId Item; FLHEntityId Target; }`: Item = owned inventory instance, Target unset = self (final field names in your doc). Add `virtual FLHCommandResult Execute(const FLHUseItemRequest&) = 0;` to `ILHCommandHandler`. Append the reason codes item use needs, e.g. `NotUsable` (item has no use effect) and `NoEffect` (would change nothing, e.g. full mana; rejected unconsumed). Append only; W4-03 consumes these and adds none. Add `LH_UNSUPPORTED(FLHUseItemRequest)` to `LHWave2Session.h` and `UNUSED_COMMAND(FLHUseItemRequest)` to the UI test double, one line each and nothing else (W4-06 replaces the stub). Contract comment: owner comes from context; UseItem is a **persisted** command (it consumes inventory: receipt + save through W4-06's wrapper), unlike UseAbility.
3. **Codec rev 2.** `SchemaVersion` default 2; publish `LHSave::CurrentSchemaVersion` and use it in validation and at `LHCharacterAuthority.cpp:882` (one-line edit). Add the canonical `UseItem` request wire to `DispatchRequest` (`Valid()`: request ID and epoch valid, item entity valid, target unset or valid). Freeze the rev-2 wire (`LHSaveWireV2.inl` or a v2 dispatch entry); keep `LHSaveWireV1.inl` as the bounded v1 decoder. Keep `PayloadCodec` `LHCanonicalBinary1` unless the D04 byte rules change (record the choice). FutureSchema becomes `>2`.
4. **Migration rev1→rev2.** Dispatch `{1, DecodeV1AndMigrate}` and `{2, DecodeIdentityV2}`: decode canonical v1, then migrate into a new validated rev-2 snapshot (header version 2; no rewrite of growth history, claims, finalized loot, receipts/epoch or high-water facts). `Decode` runs its header-canonicality check after `DecodeAndMigrate`: compare the **pre-migration** v1 header encoding against the original bytes, not the bumped rev-2 header. Store: a migrated save keeps the original rev-1 generation until a rev-2 write to the other A/B slot succeeds (freeze migration rule); edit `LHSaveStore.*` only if it doesn't already behave this way. Unsupported or ambiguous versions still reject visibly.
5. **Decision record `docs/implementation/schema-rev2.md`** (status **Proposed**, for coordinator acceptance like S-01): change list (request, handler overload, reason tokens, version), reason (Matt Q5), wire and golden vectors, migration, compatibility (rev-1 builds reject rev-2 saves as FutureSchema; rev-2 saves may hold UseItem receipts), contract corrections for `contracts-v1.md` (twelve `Execute` overloads; the coordinator applies them), a D09 note (Balork uses `RespawnPolicy=OrdinaryRepeat` with the Bible's 15:00 respawn, Matt Q4, while the boss-completion reward stays single-claim via `BossUnique`), and the hand-offs to W4-03/05/06.

- `Lighthaven.Core.Schema.UseItemRequest`: defaults are invalid; new reason tokens round-trip by name; the handler overload exists.
