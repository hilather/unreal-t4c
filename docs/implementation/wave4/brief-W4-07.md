1. **Offer catalog (`Source/Lighthaven/Services/LHServiceCatalog.*`).** Native rows `Offer.*` (D17 reserved prefix), keyed by NPC **DefinitionId** (not GUID): kind (TrainSkill / LearnSpell / BuyItem), subject (`Skill.Attack`/`Skill.Dodge`/`Skill.Archery`, `Spell.*`, `Item.*`), gold and skill-point price, rank cap, provenance.    - Temple: Kilhiam → `Spell.Light`, Moonrock → `Spell.HealLight`. Mage tower: Iraltok → `Spell.FireDart`, Uranos → `Spell.StoneShard`. B1: Shovanis → `Spell.DustDevil`. Spell prices/points/minima come from W4-03's catalog (single source; no copy).

   - Stock is unlimited and not persisted (no schema change). A persisted stock/restock/buyback model would need a later schema revision (rev 2 is UseItem only); record that as an explicit decision (Matt Q6).
2. **Authority (`Services/LHServiceAuthority.*`).** `ELHCommandReason LHServices::Execute(const FLHServiceContext&, FLHSaveSnapshot& InOut, const FLHTrainSkillRequest&)` and overloads for Learn/Buy/Sell. `FLHServiceContext` carries the resolved NPC DefinitionId + entity, distance, LOS, the character profile and the ability/item lookups (W4-06 fills it from actors and catalogs). Validate the actual offer at that NPC, proximity (lookup distance, else Prototype; same convention as portal interaction, recorded), alive/not-busy, prerequisites (level, base attributes per the lookup's requirement basis (Prototype if `missing`), prior spells), shared skill-point pool, gold, capacity and checked overflow, then commit **all-or-nothing** on a copy and Import-validate before swapping. Receipts are added around your function by W4-06's session wrapper (`LHSave::BeginRequest/CommitRequest`); your idempotency test composes the same helpers: a double-click with the same RequestId replays, a new RequestId is a new purchase. A Train request's `Points` is the number of ranks to buy.
3. **Read model.** `LHServices::Offers(const FLHContentId& Npc, const FLHSaveSnapshot&) -> TArray<FLHServiceOfferView>` (price, eligibility, reason) for W4-06 to adapt into W4-05's UI view; no UI includes.

5. **Placement instructions** in `docs/implementation/services.md`: an NPC → area → offers table; for B1, two `ALHInteractableMarker`s `NPC.Nevanis`/`NPC.Shovanis` at the existing `B1.NPC.*` positions with freshly minted literal GUIDs in the generator, interaction pads clear of arrivals/walk strips. Include an affordability note: from the Bible starting character (lookup: gold, skill points), what normal kills must earn before the first spell/bow; W4-06 tests it with real data.

## Acceptance (`Lighthaven.Services.*`)
- `Lighthaven.Services.TrainSkillSuccessAndPool`: trains N ranks; gold and points deducted once; rank cap enforced.
- `Lighthaven.Services.LearnSpellPrerequisites`: level/attribute/prereq failures reject; success adds the spell once; relearn rejects; learning cost is not the cast cost.
- `Lighthaven.Services.BuyBowAndQuiver`: buy both from Sigfried; insufficient gold rejects with no mutation; the bought quiver is equipable and unlimited.
- `Lighthaven.Services.FullInventoryRejectsIntact`: buy with full inventory → `InventoryFull`, gold/inventory unchanged.
- `Lighthaven.Services.DoubleClickIdempotent`: same RequestId twice → one purchase/training, the second is `bReplay`.
- `Lighthaven.Services.WrongNpcOrRange`: offer not at that NPC, out of range or no LOS rejects.
- `Lighthaven.Services.SellRules`: resolved price sells; equipped or unresolved rejects.
- `Lighthaven.Services.CatalogSourcePositions`: every offer NPC is in its documented area (Iraltok/Uranos at the mage tower, Shovanis B1); no debug/free offers.
