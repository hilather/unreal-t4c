## Source changes

`build/build-art.sh` exports and validates the full W5-16 NPC roster after the player step, then invokes `Source/Lighthaven/Visual/Npc/import_npc.py`. `LH_ART_NPC_ONLY=1` is an iteration option requiring real player packages already present; normal runs import the player first. `LH_ART_PLAYER_ONLY=1` retains its original player-only behavior. Export/import receipts hash actual inputs and output files. Repeated exports skip Blender construction only when all twenty output hashes still match; repeated imports require an exact package inventory. Failed changed imports invalidate their old receipt. No worker-created receipt or binary package is committed.

The importer splits the two canonical shared kits into their forty used geometry modules, applies the player's exact glTF basis conversion, verifies imported bounds against real POSITION accessors (maximum 0.5 cm error), and checks every bone name, parent and reference pose before sharing the corresponding player A/B skeleton. Only two clips per body remain. Identical texture PNG bytes reuse player texture assets; the distinct NPC textile images are shared by all NPC materials. Automatic duplicate skeletons/textures/materials and unused import products are removed after rebinding in one batch. The editor-only Interchange import snapshot is dropped from NPC meshes; complete MeshDescriptions remain available for DDC rebuilds. NPC reimport is through the source script, rather than the editor Reimport menu. Changed or partial NPC folders are staged under local Saved/ backups before editor startup, avoiding edits to assets rooted by native CDO hard references. Every visible module/material/action is hard-referenced by a per-NPC appearance DataAsset, and the marker's native component holds hard references to all fifteen appearance assets. A receipt is written only after saving real packages and enforcing the decimal **8,000,000-byte** NPC package budget.

All interactable markers receive the default native scene component; only roster NPC identities activate it. It assembles the selected modules at the marker's floor pivot with matching facing and one roster stature scale, no player capsule offset. The entire imported character must resolve before its exact registered fallback figures are hidden. Missing or incompatible assets leave the fallback visible. Meshes have NoCollision and cannot affect navigation. Presentation never modifies identity, marker transforms, services, quests, saves or interaction ranges. No generator placement, UI/controller, Core or schema change is needed.

Prototype presentation timing: one two-second gesture per twenty-second cycle, with a phase derived from the identity CRC. This replaces the dropped dialogue-driven requirement. No gameplay randomness is consumed. The clips are stationary; there is no dialogue-driven state, facial animation or dedicated blend graph. Existing W5-16 stature/colours remain prototype art values.

Three automation fixtures cover explicit fallback ownership and missing-asset restoration, every imported roster assembly (skeleton, real source bounds within 0.5 cm, upright axis, facing, stature, modules and collision), and the real generated hub/B1 markers (13+2 identities, fallback registrations, transforms and unchanged interaction-reach boundaries).
