# W4-12 durable Light effect

Candidate implementation, schema revision 2 unchanged. `Effect.SpellLight` is the only timed Stage 1 effect in W4-03's native catalog; Heal Light and damage spells are instant. No Core or wire-layout edits. Empty effects remain no Light, including migrated empty rev-1 saves.

The existing `FLHDurableEffectRecord` holds owner, self source, resolved remaining active seconds (strictly positive through 600), and resolved stacks=1. `CanonicalInputs` contains exactly `EpochA`, `EpochB`, `EpochC`, `EpochD`, in that order: resolved binary64 representations of the active request epoch's four uint32 words. Every uint32 is exactly representable. Inputs carry metadata only, no modifiers. The save validator requires valid same-run entities in registered snapshot areas, the exact case-sensitive effect name, matching epoch words, and at most one record. Unknown effects, duplicate effects, arbitrary inputs, expired entries, stacked effects, mismatched sources/epochs and unbounded/nonfinite durations reject. The existing bounded canonical encoder/decoder supplies field order, exact byte comparison and allocation caps; no alternative encoding is introduced.

`LHSave::MakeDurableLight` creates the record; `ValidateDurableLight` validates it. `LHAbilities::CaptureLightEffect` writes a completed-boundary session record; `RestoreLightEffect` validates owner and epoch then replaces the runtime remainder atomically. Empty restore clears Light. Capture removes expired effects. The runtime component exposes `RestoreLightRemainingSeconds` and `AdvanceLightEffect(ActiveSeconds, GamePaused, AIPaused, Travel)`. Advance subtracts once only when all pause flags are false. Invalid input rejects without mutation. Restore applies no elapsed time, uses no world-time deadline and creates no timer callback. Avatar detachment preserves the remainder for travel.

## Integration contract for W4-06

The session must call AdvanceLightEffect exactly once per active simulation interval. Component TickComponent never advances Light. Pass game/menu pause, AI pause and travel state; capture before replacing a component, synchronize the snapshot at completed settlement/save boundaries, restore after installing resources/actor identity, and use the accessor for presentation. A new game/death policy that clears Light should explicitly restore zero. Recasting refreshes to the catalog duration at impact. Session wiring is outside this task's ownership; until wired, casting shows Light but its explicit clock will not advance in the W4-06b session. This is an integration prerequisite, not a play result.

Request epoch here is the selected saved session epoch, not a new effect activation identifier. If later session policy rotates that epoch, capture with the new epoch before saving; stale encoded effects reject. Owner identities across travel must be explicitly remapped by the session before capture/restore if their origin-area identity changes.
