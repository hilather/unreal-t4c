# W2-01b — local persistence

Implementation against frozen schema revision 1, base `35719fdce668dd9292ad3364e9645d4a8d4fd4ac`. Core headers are unchanged. This is a submission candidate, not a G2 approval. Native runtime tests and packaged relaunch remain host work; Windows is deferred.

`ULHSaveSubsystem` owns a `FLHSaveStore` for the game instance. The default local storage adapter uses `Saved/SaveGames/Lighthaven/<CharacterId digits>.A.lhs` and `.B.lhs`. Character enumeration includes unreadable profiles, identifies characters by GUID rather than name, and returns compatibility/recovery status. No index save is required. The store can also accept an injected `ILHSaveStorage` for native failure tests. This Linux-first adapter deliberately opens a local file handle and checks its size before allocating; the generic platform `LoadGame` API allocates its file buffer internally without the D05 bound. A console/platform-specific adapter would need the same bounded-read guarantee.

Configure the subsystem once with the authoritative ruleset reference, content SHA-256, ruleset level-transition count (`MaxGrowthAwards`, at most 4,096), and `ValidateReferences` callback. The callback must resolve canonical spelling/known mandatory definitions, validate selected generator/appearance policy, authored entrance safety, equipment eligibility, historical grants and owner/source references. The game-instance wrapper refuses operation without this callback; lower-level codec/store tests intentionally exercise structural validation independently. These checks require authoritative content and cannot be inferred from a hash or invented by persistence. Ruleset/catalog hash production belongs to the rules/content authority; persistence verifies their explicit algorithm, syntax and exact compatibility. `BuildId` is informational, not a substitute for rules/catalog compatibility.

## Byte contract

`LHSaveWireV1.inl` is a checked-in explicit typed allowlist for every save field, not a reflection serializer or a generator needed at build/runtime. Structs encode their field count and field-name/value pairs in ASCII field-name order, including all fields. Missing, duplicate, reordered or unknown fields reject. Enums use symbolic ASCII tokens. Integers/GUID words/counts are little endian; GUIDs use A/B/C/D words. Bool is exactly 0/1. Doubles are finite IEEE-754 binary64; negative zero normalizes to positive zero. UTF-8 strings have a uint32 byte count, no terminator/BOM; invalid, overlong, surrogate, embedded NUL and BOM input rejects. Tokens/names and display names have their 128-byte limits. No compression, object memory, UObject pointers or platform archive bytes participate.

The transform struct has fields `RotationXYZW`, `ScaleXYZ`, `TranslationXYZ` in that order. Each coordinate vector is a fixed-size double array (uint32 count 4/3/3 followed by binary64 coordinates). Quaternion squared norm must be within 1e-6 of one; scales must be positive. Canonical quaternion sign is first nonzero W/X/Y/Z positive. An unresolved checkpoint transform is identity; unresolved number/integer storage is zero while resolution/provenance remain distinct. Runtime-required values still reject unresolved.

Payload is precisely `{Character, Session, World}` in canonical field order. Ordered answers, growth history and diagnostics retain order. Keyed collections sort by encoded keys and reject duplicates; encounter keys explicitly encode area/slot/generation. Roll/RNG records sort by StreamId. Equipment sorts by slot token, cooldowns by owner/ability, receipts by request GUID, durable effects by owner/effect/source. Decoding re-encodes and compares the entire payload and envelope, enforcing sorting, normalization and spelling as well as field structure.

File layout is six raw ASCII bytes `LHSave`, uint32 envelope byte count, canonical header, canonical payload. Header carries magic/schema/sequence/build/rules/content/character/length/algorithm/codec/checksum. Algorithm is `SHA256`, codec is `LHCanonicalBinary1`, payload checksum is lowercase 64-hex SHA-256 of payload bytes only. Header is not authenticated. `LHSha256.cpp` contains a portable FIPS 180-4 implementation because UE's generic SHA256 platform method has no Linux implementation here; native tests include empty, abc and million-a published algorithm vectors.

D05 limits: file 16 MiB, header 64 KiB, payload 15 MiB, nesting 16, aggregate collection elements 100,000, ordinary UTF-8 string 4,096 bytes. All collection-specific limits from D05 are enforced, including state bytes 64, appearance 16, answers 4, inventory/contained items 512, equipment 8, RNG streams 4,096, historical rolls 16, cooldowns 1,024, effects 1,024 and receipts 4,096. Diagnostics are at most 64 strings of 512 bytes (32 KiB combined), and are rejected rather than dropping caller evidence. Flags/marks/dialogue use a conservative 256-entry ID-set cap because D05 does not list them separately. Creation historical RNG inputs use the historical-roll cap 16. Limits are engineering bounds, not authentic T4C tuning.

The file adapter checks open-handle size before allocating the file buffer. Codec checks envelope/header/payload lengths, algorithm, codec and future schema before payload parsing. An initial walk validates the full payload's strings, depth and counts with no TArray collection allocation; only bounded enum token strings are materialized. The second walk allocates collections. `FLHSaveDecodeStats` exposes whether this second walk began for adversarial native tests. Per-array count comparisons precede allocation and avoid count multiplication. Ruleset-specific growth capacity is also enforced in the first walk. The file buffer and bounded header/token strings are separate from payload collection allocation.

## Generation and request lifecycle

Both files are read/validated against the selected character and current compatibility. Load selects the highest complete compatible sequence. One rejected nonmissing slot plus one valid slot emits `Recovered` with its structured reason and both slot diagnostics; this intentionally errs toward warning even when a corrupt file cannot reveal its former sequence. Equal-sequence different valid files reject as ambiguous. All-invalid emits `Unreadable`, leaves the output snapshot unchanged, preserves files and never creates a character. `NotFound`, `FutureSchema`, unsupported schema/algorithm/codec, incompatible rules/catalog, checksum, bounds, malformed data and epoch mismatch are distinct reasons. The UI can implement the character-select recovery acknowledgment and retry/back/details flows from these events; persistence itself draws no UI and supplies no fabricated timestamps.

RequestSave copies the caller's completed snapshot. One write per character can be active; newer requests replace only the pending snapshot. Load/enumeration of that character reports Busy during a write. Different characters may save independently. Write selects the slot opposite the newest valid one (or A for a genuinely absent profile), reserves the operation before reading/encoding, and advances sequence to max(previous + 1, caller transaction sequence). Sequence exhaustion rejects; it never wraps. This preserves receipt transaction ordering supplied by authority. The caller must never request an older logical state as a new mutation.

File write runs on the thread pool; completion runs on the game thread. Full file flush and exact readback/digest/codec validation precede success. The previous valid file is never the target. A failure preserves the newest pending snapshot, or reinstates the failed snapshot if no newer one exists, and emits `Failed` (progress not safely saved). Retry is explicit; no infinite retry loop. A successful completion publishes its sequence and starts the latest pending snapshot. Re-entrant event subscribers are supported by reacquiring map state after publication. Store lifetime is weakly referenced by completions, so game-instance teardown cannot call a destroyed UObject; quitting with a write in flight is not a promised successful save. The application must wait for the matching success before quit/travel/respawn durability decisions. A/B plus flush/readback is not a promise of atomic platform writes or survival of every power/disk failure.

The authority must pass `bCompletedActionBoundary=true` only after all pending activation/impact, transfers, death/rewards, travel transition and callback-publication stacks have settled/cancelled and simulation is frozen as needed. Persistence cannot inspect actors to certify this. Cooldown remainder, fractional mana carry, gameplay RNG seed bytes, retained receipts/claims, encounter high-water and finalized corpse contents are durable values; no wall-clock catch-up or RNG reset occurs. The v1 durable-effect allowlist is empty, so any nonempty durable effect array rejects. Unknown gameplay RNG algorithms/revisions or receipt epochs reject. Resolved required counters/resources/timers are nonnegative and finite; current resource clamping follows equipment/effect reconstruction in the authority.

Travel integration: source checkpoint save must succeed before loading destination; suppress unrelated requests during transition; validate destination then save arrival. On destination failure restore durable source. Death integration: settle consequence/reward/inventory/checkpoint once, save, then respawn. The owner must await the matching succeeded sequence and keep source/runtime state available on failure. These gameplay transitions belong to W2-04/W3-04/W4-04 and are not wired by this owned-path-only task.

## Migration seam and tests

The version dispatch table supports schema 1 identity only. No migration is offered from planning JSON, missing fields, changed rules, aliases or future layouts. Incompatible rules/catalog need an explicit migration/new-character decision; they never reinterpret data. A future migration must supply its own bounded decoder and validated transformation and write only the older slot while retaining the source generation.

Native tests under `Lighthaven.Persistence.*` cover populated roundtrip, exact deterministic bytes/set permutation, SHA256 vectors and golden struct/GUID/binary64 byte prefixes, zero/unresolved/quaternion canonicalization, bad checksum fallback, interrupted/truncated write, future/unknown schema/algorithm/codec, byte/count/string caps before collection allocation, both slots bad with visible error/no replacement, request epoch mismatch, coalescing/immutability/failure/retry/Busy, malformed UTF-8/fields/trailing bytes, duplicate keys, compatibility and bounded local file enumeration/read. Additional coverage checks per-ruleset growth bounds, registry callback rejection, exhaustion, independent characters, exact readback and async local write/reopen.

The canonical test emits a synthetic encoder-produced `.lhs` and full-file `.sha256` beneath `Saved/Automation/Persistence/` when run; no save fixture was manually fabricated or claimed produced in this root worker. The coordinator can archive these after native tests. Test snapshots explicitly label numbers Prototype/synthetic; no game-mechanics defaults or source authenticity are introduced. No test worlds or actors are used, so the world/controller/timer fixture conventions do not apply.

## W2-01c — malformed test crash and unity helpers

The duplicate-inventory mutation now copies the first item to a local value before adding it back to the inventory. Passing an inventory element directly to the same TArray's Add triggers Unreal's self-alias check; reserving capacity alone does not bypass that check. The malformed/compatibility cases remain, and duplicate inventory rejection now also asserts InvalidSnapshot.

The owned persistence sources and wire include were inspected for Add/AddUnique/Append/Insert/Emplace aliases. The sole self-aliasing mutation found was the duplicate-inventory test. Codec Raw writes append stack values, UTF-8 conversion buffers, or a separate header/payload wire's output; keyed-array entries are built from a separate values array. Truncation uses SetNum and the interrupted-write fixture moves its queued write into a local before removing it.

File-local helpers now live in file-unique namespaces: LHSaveCodecPrivate (including LHSaveWireV1.inl), LHSaveValidationPrivate, LHLocalSaveStoragePrivate and LHPersistenceTestsPrivate. Public entry points and test bodies use qualified names or function-scoped using directives, so helper names are not imported at unity translation-unit scope. LHSaveStore.cpp, LHSaveSubsystem.cpp and LHSha256.cpp have no free file-local helpers; their lambdas/constants remain function-local.
